# 公司互動心智圖

抓 MoneyDJ「公司互動」頁（供應商、客戶、競爭者、轉投資、被投資、策略聯盟），
畫成可以一層一層點開的心智圖。輸出是單一 HTML 檔，不需要網路，雙擊就能用瀏覽器打開。

另外補五個來源，把 MoneyDJ 漏掉的關係補進來：

| 來源 | 補進哪裡 | 可信度 |
| --- | --- | --- |
| 證交所／櫃買中心 OpenAPI：持股逾 10% 大股東、董監事持股（法人董事） | 被投資、轉投資 | 高：官方申報的事實。名字旁會標「大股東 15.59%」「董事 3.65%」這類標籤 |
| 櫃買中心產業價值鏈（ic.tpex.org.tw） | 產業鏈同業 | 低：只代表「同一個產業環節」，不是實際買賣。圖上用**虛線**表示是推論 |
| 新聞標題、法說會簡報（本機 Qwen 抽取，`llm_rel.py`） | 客戶、供應商、策略聯盟 | 中：有引用原文，但模型可能誤判。只有這個來源的公司外框是**細點虛線** |
| MOPS 重大訊息的設備／工程採購公告（`capex.py`，讀 supply-chain-radar 的 `radar.db`、`backtest.db`） | 供應商（發布公司向誰買）、客戶（對方是上市櫃時，反向補進對方的客戶） | 高：官方公告寫明的交易相對人與金額，但只涵蓋設備、工程、廠房採購，期間依 radar 資料庫而定。標籤是標的或「n 筆」加合計金額（例如 `機器設備 10.3億`） |
| MOPS 重大訊息的合約公告（`capex.py` 的 `load_contracts`，同樣讀 `radar.db`、`backtest.db`；src 為 `contract`，來源欄寫「重大訊息合約公告」） | 發布公司是賣方（承攬、得標、供貨、銷售）：發布公司的客戶、對方（有代號）的供應商；是買方（委託、發包、採購）：反過來。政府機關、外國公司只當發布公司的項目 | 高：公司自己的公告，對象與金額是公告寫明的；但量少，多為營建、標案、醫材與藥品授權。方向看不出來、相對人匿名（「某公司」）、經銷／代理、融資、租賃、合建、糾紛、更正、擬簽訂的一律不收；已被 capex 收走的設備／工程／廠房公告不重複收。相對人有多家時不填金額。面板明細的來源欄寫「合約」連到公告 |
| 政府電子採購網決標公告（`pcc.py`，g0v 鏡像 pcc-api.openfun.app） | 客戶（每個政府機關一項，近 5 年合計金額前 20 名） | 高：官方決標紀錄。標籤是「標案 n 筆」加合計金額，面板明細的來源欄寫「決標」連到公告。只代表賣給政府機關；鏡像資料可能落後官方網站；3 年以前的決標沒抓明細，沒有金額 |

多個來源跟 MoneyDJ 重複的公司會併在一起（來源欄會同時寫 MoneyDJ 和官方申報）。

> 研究輔助工具，不是投資建議。資料來自 MoneyDJ、證交所、櫃買中心等第三方，可能不完整或過時；產業鏈同業只是推論。
> 使用前請先看文末的[免責聲明](#免責聲明)與[著作權與資料來源](#著作權與資料來源)。

本版本庫**只有程式碼**，不含任何抓下來的資料或產生的報表（`data/`、`reports/` 都在 `.gitignore` 裡），第一次執行時會自己抓。

## 安裝

```
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 使用

```
.venv\Scripts\python.exe relations.py 1101 2330        # 代號或簡稱，可以多個
.venv\Scripts\python.exe relations.py 台泥 --depth 2   # 再往外抓一層（通常上百家，每家間隔 1 秒）
.venv\Scripts\python.exe relations.py 1101 --refresh   # 忽略快取，全部重抓
.venv\Scripts\python.exe relations.py 1101 --skip-official --skip-chain   # 只用 MoneyDJ
```

產生 `reports/relations-代號-日期.html`。

- 預設往外抓一層：根公司和它直接相關的台股都會抓，所以圖上這些公司可以再點開
- MoneyDJ 頁面快取在 `data/relations/`，30 天內不重抓
- `--skip-official`：不補官方持股申報；`--skip-chain`：不補櫃買產業鏈同業；`--skip-llm`：不補 LLM 抽取的關係；`--skip-capex`：不補重大訊息的設備／工程採購；`--skip-contract`：不補重大訊息的合約公告；`--skip-pcc`：不補政府採購決標
- 官方資料（上市櫃名單、大股東、董監事持股）快取在 `data/openapi/`，名單 30 天、持股 7 天自動更新；名單用來把沒附代號的公司名對到代號、標上市／上櫃／興櫃
- 櫃買產業鏈快取在 `data/ic_chain.json`，30 天內不重抓（第一次要逐個產業抓，約一分鐘）

## 新聞／法說會的供應鏈關係（llm_rel.py）

用本機 LM Studio（預設 `qwen/qwen3-14b`，`http://localhost:1234/v1`）讀 supply-chain-radar 的 `radar.db`（唯讀），
從新聞標題（含「訂單、打入、供應鏈、認證…」等關鍵字、沒有內文的）和法說會簡報（關鍵字前後各一行）抽出「A 供應 B」「A 與 B 合作」，
存到 `data/llm_relations.json`；之後執行 `relations.py` 會自動併進圖裡。

```
.venv\Scripts\python.exe llm_rel.py --limit 6 --only titles          # 先小量試跑，最多呼叫 6 次
.venv\Scripts\python.exe llm_rel.py --only presentations             # 法說會簡報
.venv\Scripts\python.exe llm_rel.py                                  # 全部；可以 Ctrl-C，下次接著跑
```

參數：`--radar-db` 資料庫路徑、`--base-url`、`--model`、`--batch`（每次呼叫放幾則標題，預設 12）。

每一筆抽取結果要過四道檢查才保留，被丟掉的原因和各 5 筆範例記在 `llm_relations.json` 的 `stats`：

1. `evidence_not_found`：模型引用的原文，必須逐字出現在來源（那則標題或那段簡報）裡
2. `name_not_in_text`：供應方、客戶的名稱都必須出現在來源文字裡（簡報的「本公司」視為發行公司）
3. `no_tw_company`：兩邊至少一邊要對得上台股公司（簡稱、全名、去掉 -KY 都試）；另一邊對不上就當純文字
4. `self`：兩邊不能是同一家

**可信度中等**：Qwen 是抽取不是查證，可能把泛稱（「韓系客戶」）、機構或產品當成公司，也可能誤判方向，請對照點開面板裡的引用原文和連結。
圖上的標籤：`新聞`、`法說`＝證據來源類型（取最新一筆）；`傳`＝所有證據都是「傳、可望、有望、洽談」之類不確定的語氣。
面板會列出最多 3 筆引用（新的在前），連結可以開原文。

## 政府採購決標（pcc.py）

用統一編號查 g0v 的政府電子採購網鏡像（`https://pcc-api.openfun.app`），留下上市櫃公司「得標」的決標／更正決標公告（同一標案取最新一筆）；
近 3 年的最多讀 50 筆明細取得金額與品項，更早的只留標題、日期、機關。結果存到 `data/pcc/代號.json`，30 天內不重抓，中斷後重跑會接著做。
請求間隔至少 1 秒；全部上市櫃約 1.3 萬個請求、數小時，建議分批跑。

```
.venv\Scripts\python.exe pcc.py --codes 2412 3231 6196   # 指定公司
.venv\Scripts\python.exe pcc.py --limit 20               # 全市場，最多抓 20 家（已有新快取的不算）
.venv\Scripts\python.exe pcc.py                          # 全部上市櫃，可以 Ctrl-C，下次接著跑
```

參數：`--refresh` 忽略快取、`--since-years`（抓明細的年數，預設 3）、`--max-details`（每家最多幾筆明細，預設 50）。
可信度高，但只代表「賣給政府機關」；鏡像可能落後官方網站，執行結束會印出最新的決標日期。

## 心智圖怎麼看

- 中間是公司本身；左邊是上游、股東與同環節公司（供應商、被投資、策略聯盟、產業鏈同業），右邊是下游與同業（客戶、轉投資、競爭者）
- 台股公司右側的「＋ 數字」按鈕往外展開它自己的關係，數字是它有幾筆關係；↺ 表示已經在上層出現過
- 超過 14 筆的類別先只畫 10 筆，點「＋ 還有 N 家」展開
- 公司名字旁的小標籤是官方持股資訊：「大股東 15.59%」＝持股逾 10% 的大股東；「董事 3.65%」「監察人 4.84%」＝法人董監事，百分比是它持有的股份比例
- 虛線連線＝推論（產業鏈同業：同在櫃買的某個產業環節，不代表有買賣）。這類不算進「N 筆關係」
- 公司名字旁的小色點：同一家公司在這個母公司底下還屬於其他類別（例如嘉泥對台泥同時是競爭者、客戶、被投資）
- 虛線框的台股：還沒抓，或 MoneyDJ 沒有資料（多半是興櫃或剛掛牌）
- 滑鼠停在公司上，會標出它在圖上出現的所有位置
- 點公司打開細節：關係來源與說明（例如法人全名、持股張數）、它在櫃買產業鏈的位置、它自己的關係數量、「已抓的公司裡，誰把它列為供應商／客戶／競爭者」
- 有往來明細的項目（重大訊息採購、LLM 抽取）面板會多一段表格：日期、標的／內容、金額、來源連結。供應商底下標題是「X 供應給 Y 的東西」，客戶底下是「Y 賣給 X 的東西」，最多列 15 筆，其餘寫「還有 N 筆」
- 雙擊或按「以它為中心」換中心；上方搜尋框也可以直接換中心，← 回上一個
- 上方類別色塊可以隱藏或顯示某一類；拖曳平移、滾輪縮放（手機兩指縮放）

## 檔案

- `relations.py`：MoneyDJ 爬蟲、解析，合併五個來源後輸出
- `official.py`：證交所／櫃買 OpenAPI：上市櫃名單、大股東、董監事持股
- `ic_chain.py`：櫃買中心產業價值鏈
- `capex.py`：從 radar.db／backtest.db 的重大訊息解析設備／工程採購公告，另有 `load_contracts` 解析合約公告（先判斷發布公司是賣方或買方）；解析規則複製自 supply-chain-radar 的 `radar/material.py`，兩邊要保持同步
- `pcc.py`：政府電子採購網決標公告（g0v 鏡像）：每家上市櫃公司得標的標案、金額、機關
- `llm_rel.py`：用本機 LLM 從新聞標題、法說會簡報抽取供應／合作關係
- `relations.html`：心智圖頁面樣板（資料會塞進 `/*__DATA__*/null` 的位置）
- `news_body.py`：抓新聞內文（供 `llm_rel.py` 使用）

`capex.py`、`llm_rel.py`、`news_body.py` 讀的是另一個專案 supply-chain-radar 的 `radar.db`／`backtest.db`（預設路徑是本專案旁邊的 `../supply-chain-radar/data/`），該專案不在本版本庫內；沒有這些資料庫時，用 `--skip-capex --skip-contract --skip-llm` 跳過即可。
